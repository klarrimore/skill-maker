# Agent Skills: Latest Trends and Best Practices

**Date researched:** 2026-10-25  
**Comparison baseline:** The repository's prior primary-source refreshes dated 2026-09-30, especially [`agentskills-spec-and-best-practices.md`](./agentskills-spec-and-best-practices.md), [`claude-skills-spec-and-best-practices.md`](./claude-skills-spec-and-best-practices.md), and [`codex-skills-spec-and-best-practices.md`](./codex-skills-spec-and-best-practices.md).

## Summary of key findings

1. **The normative agentskills.io format has not materially changed since the September 30 check.** The current specification still requires `name` and `description`, permits `license`, `compatibility`, `metadata`, and experimental `allowed-tools`, and retains the same directory structure and progressive-disclosure budgets. The public repository's current commit history still ends with the August 9, 2026 OpenClaw showcase commit, so there is no new schema revision, version tag, or formal spec changelog to adopt. ([specification](https://agentskills.io/specification), [current specification source](https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx), [commit history](https://github.com/agentskills/agentskills/commits/main))
2. **There is strong runtime convergence around the portable core, but not around the host contract.** Claude Code, Codex, Cline, Cursor, OpenCode, Gemini/Antigravity, VS Code/GitHub Copilot, and other clients all document `SKILL.md` bundles, metadata-first loading, and on-demand instructions/resources. They diverge on search paths, precedence, same-name collisions, permissions/consent, slash commands, and optional frontmatter. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [Cline](https://docs.cline.bot/customization/skills), [Cursor](https://cursor.com/docs/skills), [OpenCode](https://opencode.ai/docs/skills/), [Antigravity](https://antigravity.google/docs/skills), [VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills))
3. **Description quality is now treated as an empirical routing problem, not copywriting polish.** The standard's description guide recommends realistic positive and near-miss negative queries, repeated runs, trigger-rate measurement, and fixed train/validation splits. Codex additionally warns that its catalog is capped and descriptions may be shortened, so authors should front-load scope and trigger words. ([description optimization](https://agentskills.io/skill-creation/optimizing-descriptions), [Codex build-skills guide](https://developers.openai.com/codex/skills))
4. **Evaluation is moving from ad-hoc demonstrations to repeatable, baseline-comparative, evidence-backed suites.** The agentskills.io guide specifies `evals/evals.json`, with-skill versus without-skill runs, assertions, timing, human review, and iteration. Microsoft's Waza now provides a dedicated CLI for skill/workflow evaluation, deterministic graders, fixtures, coverage checks, preflight validation, and CI gates; VS Code documents Waza integration for skill files. ([evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills), [Waza Quick Start](https://microsoft.github.io/waza/quick-start/), [Waza eval guide](https://microsoft.github.io/waza/guides/eval-yaml/), [VS Code customization overview](https://code.visualstudio.com/docs/agent-customization/overview))
5. **Distribution is becoming package- and marketplace-oriented, while no central agentskills.io skill registry exists.** OpenAI now directs reusable distribution toward plugins and a universal plugin directory; Vercel's `skills` CLI and `skills.sh` provide multi-agent install/search/update flows and popularity leaderboards; GitHub CLI has preview `gh skill search|preview|install|update|publish` commands with pinning and provenance metadata; VS Code has an experimental customization marketplace. The agentskills.io repository still explicitly says it does not maintain a community skill directory. ([OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Vercel skills CLI](https://github.com/vercel-labs/skills), [skills.sh](https://skills.sh), [GitHub Copilot skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [agentskills.io contribution policy](https://github.com/agentskills/agentskills/blob/main/CONTRIBUTING.md))
6. **Security and provenance are becoming part of the installation UX.** GitHub warns that skills are not verified and may contain prompt injections or malicious scripts, and exposes preview-before-install plus version pinning. Gemini/Antigravity presents consent and directory-access steps, while the agentskills.io client guide recommends trust gating for repository skills. ([GitHub Copilot skill installation](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [Gemini CLI skills](https://geminicli.com/docs/cli/skills/), [Antigravity skills](https://antigravity.google/docs/skills), [client implementation guide](https://agentskills.io/client-implementation/adding-skills-support))
7. **Companion standards are emerging without changing the core spec.** Community discussions propose lockfiles, integrity hashes, provenance, attestations, and SemVer, while JetBrains adds external registry and multi-scope installation UX; these are signals for adapters, not normative requirements. ([lockfile discussion](https://github.com/agentskills/agentskills/discussions/588), [SemVer proposal](https://github.com/agentskills/agentskills/discussions/415), [JetBrains AI Assistant skills](https://www.jetbrains.com/help/ai-assistant/agent-skills.html))
8. **Hosted skill lifecycle is now a separate integration target.** Anthropic's beta Skills API versions uploaded bundles for server-side containers, and Claude Code syncs account skills across terminal, Cowork, and cloud sessions; skill-maker should preserve workspace/scope/version metadata without treating it as portable `SKILL.md` schema. ([Anthropic Skills API](https://platform.claude.com/docs/en/api/beta/skills), [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages), [Claude Code skills](https://code.claude.com/docs/en/skills))

## Findings

### 1. Normative specification status

**Claim.** The current normative schema remains the same six-field model: required `name` and `description`; optional `license`, `compatibility`, `metadata`, and experimental `allowed-tools`. `name` remains 1–64 characters and may only contain lowercase alphanumeric characters and hyphens; the detailed prose calls those characters “unicode lowercase alphanumeric” but illustrates the ranges as `a-z` and `0-9`. It must not begin or end with a hyphen, must not contain consecutive hyphens, and must match the parent directory; `description` remains non-empty and capped at 1,024 characters. The specification still defines a directory containing `SKILL.md` and optional `scripts/`, `references/`, and `assets/`; it still recommends metadata-only discovery, a body under 5,000 tokens/500 lines, and on-demand resources. No formal version number or spec changelog is exposed by the current site or repository. ([specification](https://agentskills.io/specification), [raw specification source](https://raw.githubusercontent.com/agentskills/agentskills/main/docs/specification.mdx))

**Date verified.** 2026-10-25. The public repository commit-history page still shows `69ef37e9424c0a7ea9dd2293b559e43ec8176379` (`docs: add OpenClaw to client showcase`, 2026-08-09) as the latest `main` commit. ([commit history](https://github.com/agentskills/agentskills/commits/main), [latest commit](https://github.com/agentskills/agentskills/commit/69ef37e9424c0a7ea9dd2293b559e43ec8176379))

**Relevance to skill-maker.** Treat the September 30 schema guidance as current. Do not invent a spec version, add new required metadata, or promote client extensions into the portable schema. Because the current name prose says “unicode” while showing ASCII-style `a-z`/`0-9` ranges, emit conservative ASCII slugs by default and make any broader Unicode mode explicit and test-backed rather than assuming every client accepts it. The reference `skills-ref` package is still explicitly demonstration-only, not a production SDK. ([skills-ref README](https://github.com/agentskills/agentskills/blob/main/skills-ref/README.md), [skills-ref package metadata](https://github.com/agentskills/agentskills/blob/main/skills-ref/pyproject.toml))

### 2. Cross-client convergence: the portable core

**Claim.** The major clients surveyed converge on four behaviors: a skill is a directory bundle, `SKILL.md` is the entry point, `name`/`description` are the discovery metadata, and detailed instructions/resources are loaded only after relevance is established. The agentskills.io client guide calls this three-tier progressive disclosure; Cline, Cursor, OpenCode, Gemini CLI, Antigravity, Codex, and VS Code describe materially the same model. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [Cline](https://docs.cline.bot/customization/skills), [Cursor](https://cursor.com/docs/skills), [OpenCode](https://opencode.ai/docs/skills/), [Gemini CLI](https://geminicli.com/docs/cli/skills/), [Antigravity](https://antigravity.google/docs/skills), [Codex](https://developers.openai.com/codex/skills), [VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills))

**Date verified.** 2026-10-24.

**Relevance to skill-maker.** Continue generating a boring, portable `SKILL.md` first. Treat all host-specific command names, locations, UI metadata, invocation policies, and execution contexts as adapters around that core rather than as part of the skill's main instructions.

### 3. Cross-client divergence: locations, precedence, and collisions

**Claim.** Discovery and collision rules are not portable even when the file format is. Examples from current first-party documentation:

| Client | Current behavior | Source |
| --- | --- | --- |
| Codex | Scans repository ancestors, user, admin, and system locations. Same-named skills from different scopes do not merge; both may appear in selectors. | [Codex build-skills](https://developers.openai.com/codex/skills) |
| Cline | Supports `.cline/skills/`, `.clinerules/skills/`, and `.claude/skills/`; a global skill takes precedence over a same-named project skill. | [Cline skills](https://docs.cline.bot/customization/skills) |
| Cursor | Loads `.agents/skills/`, `.cursor/skills/`, Claude/Codex-compatible directories, and nested project skills; nested skills can be scoped to files by location. | [Cursor skills](https://cursor.com/docs/skills) |
| Gemini CLI | Uses built-in, extension, user, and workspace tiers. `.agents/skills/` aliases exist alongside `.gemini/skills/`, with documented higher-tier and alias precedence. | [Gemini CLI skills](https://geminicli.com/docs/cli/skills/) |
| GitHub Copilot/VS Code | Supports `.github/skills/`, `.claude/skills/`, and `.agents/skills/`, plus personal paths; support varies by harness/surface. | [Copilot agent skills](https://docs.github.com/en/copilot/concepts/customizations/agent-skills), [VS Code agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills) |
| Claude Code | Uses enterprise, personal, project, nested, additional-directory, plugin, and synced-account locations. Local precedence and plugin namespace rules are client-specific; synced skills reserve names such as `synced` and `anthropic-skills`, and name collisions can force a namespaced invocation. | [Claude Code skills](https://code.claude.com/docs/en/skills) |
| OpenCode | Searches its own, Claude-compatible, and `.agents/skills/` paths from the current directory up to the git worktree and from global locations. | [OpenCode skills](https://opencode.ai/docs/skills/) |
| Antigravity | Defaults to `.agents/skills` while retaining `.agent/skills` compatibility; plugins add another distribution location. | [Antigravity skills](https://antigravity.google/docs/skills) |

The agentskills.io guide's “project overrides user” rule is therefore a useful convention, not a universal runtime guarantee; Cline documents the opposite for its global/project pair, and Codex documents coexistence rather than override. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support))

**Date verified.** 2026-10-25.

**Relevance to skill-maker.** The UI and generated install instructions should ask for a target client/surface and scope. A portable-mode warning should explain that `.agents/skills/` is widely adopted but not mandated by the format. Collision diagnostics should report both paths and the host's resolution rule rather than assuming project precedence. For cloud or sandboxed targets, offer an explicit upload/API/registry path instead of assuming local filesystem access, and bound scanners while skipping `.git`, `node_modules`, and other build trees. Filter disabled or permission-denied skills out of the model catalog rather than listing options that cannot activate.

### 4. Frontmatter extensions are proliferating, so portability requires restraint

**Claim.** The portable six-field set remains small, but clients now document many extensions:

- Claude Code adds invocation controls, forked/subagent execution, dynamic context injection, substitutions, and other frontmatter/runtime behavior. ([Claude Code skills](https://code.claude.com/docs/en/skills))
- VS Code/Copilot documents `argument-hint`, `user-invocable`, `disable-model-invocation`, and feature-gated `context: fork`. ([VS Code agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills))
- Cursor documents `paths`, `disable-model-invocation`, `icon`, `color`, `metadata`, and legacy `globs`; it also uses nested directories for implicit file scoping. ([Cursor skills](https://cursor.com/docs/skills))
- Codex uses a separate `agents/openai.yaml` for interface metadata, invocation policy, and tool dependencies instead of putting those concerns in `SKILL.md`. ([Codex build-skills](https://developers.openai.com/codex/skills))
- OpenCode says unknown frontmatter is ignored and only documents the standard fields for skill behavior. ([OpenCode skills](https://opencode.ai/docs/skills/))
- Antigravity treats `name` as optional and defaults it from the folder name, which is convenient in that client but does not satisfy the normative requirement that `name` be present. ([Antigravity skills](https://antigravity.google/docs/skills), [specification](https://agentskills.io/specification))

**Claim.** The client implementation guide recommends a lenient import path for cross-client compatibility: warn and still load when `name` mismatches the parent directory or exceeds the limit, but skip skills with missing/empty descriptions or completely unparseable YAML. It also recommends surfacing diagnostics rather than silently accepting malformed metadata. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support))

**Date verified.** 2026-10-25.

**Relevance to skill-maker.** Keep the default generated artifact limited to portable fields. Offer explicit, opt-in host profiles that write extensions in separate files where the host supports them. Never silently emit `context: fork`, `paths`, `user-invocable`, `disable-model-invocation`, or `agents/openai.yaml` in an “agent-agnostic” skill. Use strict validation for generated portable skills, but use a separate compatibility-import mode that warns—not rejects—known host extensions and cosmetic name violations while surfacing diagnostics; still reject missing descriptions and unparseable YAML.

### 5. Triggering and description optimization

**Claim.** The description is still the primary activation signal, but current guidance treats it as something to measure. The official optimization guide recommends about 20 realistic queries, balanced should-trigger and should-not-trigger cases, formal/casual/typo variants, buried multi-step requests, and near-miss negatives. It recommends three runs per query, a trigger-rate threshold, and a fixed train/validation split to reduce overfitting. It also recommends imperative wording, user intent rather than implementation detail, explicit boundaries, and a concise description under the 1,024-character limit. ([optimizing descriptions](https://agentskills.io/skill-creation/optimizing-descriptions), [specification](https://agentskills.io/specification))

**Claim.** Host context budgets make front-loading more important. Codex caps the initial catalog at 2% of the context window or 8,000 characters by default, can shorten descriptions, and may omit skills when the catalog is too large. Codex therefore specifically advises putting the key use case and trigger words first. ([Codex build-skills](https://developers.openai.com/codex/skills))

**Date verified.** 2026-10-24.

**Relevance to skill-maker.** Generate descriptions with the action, scope, trigger phrases, and boundary in the first sentence. Add an eval scaffold with positive, negative, and near-miss prompts. Do not claim that keyword matching alone is the standard activation mechanism: clients generally leave the final relevance decision to the model, with explicit slash/mention invocation as an escape hatch. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [Cline skills](https://docs.cline.bot/customization/skills))

### 6. Body design and progressive disclosure remain stable best practice

**Claim.** Current first-party guidance still favors focused skills, moderate detail, procedures over declarations, defaults over menus, concrete gotchas, short examples/templates, and validation loops. Long or generic material should move to one-level-deep referenced files; scripts should be used for deterministic/repeated work, with clear interfaces and helpful errors. The scripts guide now explicitly recommends pinned versions, declared prerequisites, `--help`, noninteractive arguments, structured output, and self-contained dependency declarations such as PEP 723 where practical. ([best practices](https://agentskills.io/skill-creation/best-practices), [using scripts](https://agentskills.io/skill-creation/using-scripts), [specification](https://agentskills.io/specification))

**Date verified.** 2026-10-24.

**Relevance to skill-maker.** Preserve the existing generator defaults: one coherent job per skill, a concise body, relative references, one level of reference indirection, and bundled scripts only for logic the model should not reinvent. Add a check that a referenced script exposes noninteractive usage/help and that a reference is actually conditionally addressable (“read this when…”), not just a generic directory pointer.

### 7. Evaluation is becoming a first-class engineering artifact

**Claim.** The agentskills.io evaluation guide defines a concrete structure: author `evals/evals.json` with realistic prompts, expected outputs, optional files, and later-added assertions; run with and without the skill (or against a prior snapshot); record timing/token data; grade assertions with evidence; review outputs as a human; and iterate based on failures, traces, and cost/quality deltas. It explicitly recommends deterministic checks where possible and warns against vague or brittle assertions. ([evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills))

**Claim.** Microsoft's Waza is a significant ecosystem shift beyond the lightweight JSON guide. Its published `v0.39.0` (dated October 20, 2026) supports skill/workflow eval scaffolding, preflight checks, fixtures, coverage verification, deterministic graders, evidence-backed judging, snapshots/replay, multi-model comparison, and CI integration. Its guide requires positive, negative, boundary, and realistic integration cases, prefers deterministic graders over LLM judges for mechanically checkable behavior, and distinguishes real `copilot-sdk` evaluation from the `mock` executor, which only checks harness/fixture plumbing. ([Waza Quick Start](https://microsoft.github.io/waza/quick-start/), [Waza eval-spec guide](https://microsoft.github.io/waza/guides/eval-yaml/), [Waza CI/CD](https://microsoft.github.io/waza/guides/ci-cd/), [Waza repository](https://github.com/microsoft/waza))

**Claim.** VS Code's current customization documentation integrates a Chat Customizations Evaluations extension with Waza to analyze skill contradictions/ambiguity and run skill test suites. ([VS Code customization overview](https://code.visualstudio.com/docs/agent-customization/overview))

**Claim.** Claude Code's bundled Claude API skill now exposes `build-eval` to create an eval set and `hillclimb` to iteratively improve an application against an existing eval. These are host-specific workflows rather than a replacement for the portable `evals/evals.json` artifact. ([Claude Code skills](https://code.claude.com/docs/en/skills))

**Claim.** Claude Code's `/doctor prompt-audit` provides a host-specific static review of `CLAUDE.md` files, skills, and related configuration, flagging outdated or conflicting instructions. It complements behavioral evals but does not replace them. ([Claude Code skills](https://code.claude.com/docs/en/skills))

**Date verified.** 2026-10-25; Waza's published release date is 2026-10-20.

**Relevance to skill-maker.** Keep the portable `evals/evals.json` format as the lowest-common-denominator authoring artifact, and optionally generate Waza files or Claude-specific `build-eval` inputs for teams that want CI, iterative optimization, or richer evidence. Expose baseline comparison and trigger tests in the product. Make “mock harness passed” visibly different from “agent behavior improved,” and never let a passing mock run substitute for a real model evaluation.

### 8. Installation, packaging, and marketplaces

**Claim.** Distribution is fragmenting into several compatible but non-identical channels:

- OpenAI's current guidance says standalone skills are for local authoring, while reusable skills and skills-plus-connectors should be bundled as plugins. The newer portable Agent Plugins layout uses a root `plugin.json`, `skills/` directory, and `agent-plugins.org` schema; public plugins are published to a universal directory shared by ChatGPT and Codex. Existing `.codex-plugin/plugin.json` manifests remain a compatibility fallback. OpenAI also documents local/repository marketplaces at `.agents/plugins/marketplace.json`, `codex plugin marketplace add`, upgrade tracking, and Git ref pinning; these sources are separate from the universal directory. ([OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Codex build-skills](https://developers.openai.com/codex/skills))
- Vercel's open-source `skills` CLI installs from GitHub, GitLab, Azure Repos, arbitrary git URLs, local paths, direct archives, and npm packages; it supports project/global scope, many agent targets, symlink or copy installation, update checks, and an experimental npm dependency sync. Its README advertises support for OpenCode, Claude Code, Codex, Cursor, and 75+ additional agents. ([Vercel skills repository](https://github.com/vercel-labs/skills), [supported agents](https://github.com/vercel-labs/skills/blob/main/docs/agents.md), [CLI reference](https://github.com/vercel-labs/skills/blob/main/docs/commands.md))
- Vercel's `skills.sh` is a public directory with search, all-time/trending/hot views, weekly activity, install counts, and agent filters. This is a popularity/discovery signal, not a normative quality or safety certification; the page does not define a standard rating methodology. ([skills.sh](https://skills.sh))
- GitHub CLI's public-preview `gh skill` commands search public repositories, preview the full file tree/content before installation, install to agent-specific locations, update by recorded source metadata, pin tags/SHAs, and publish validated repositories as GitHub releases. GitHub explicitly warns that skills are not verified and may contain prompt injections or malicious scripts. ([GitHub CLI skill manual](https://cli.github.com/manual/gh_skill), [skill search](https://cli.github.com/manual/gh_skill_search), [skill preview](https://cli.github.com/manual/gh_skill_preview), [skill publish](https://cli.github.com/manual/gh_skill_publish), [GitHub Copilot installation guide](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills))
- VS Code's experimental Customization Marketplace provides a Discover page for skills, MCP servers, plugins, and other customizations, with source/publisher details, install destinations, missing-file repair, and preservation of user edits. ([VS Code customization overview](https://code.visualstudio.com/docs/agent-customization/overview), [VS Code agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills))

**Claim.** The agentskills.io project itself still does not maintain a community skill directory and says skill submissions are not accepted yet. Its showcase is an adoption list, not an installable registry. ([agentskills.io contribution policy](https://github.com/agentskills/agentskills/blob/main/CONTRIBUTING.md), [client showcase](https://agentskills.io/clients))

**Claim.** Public sharing currently happens primarily by publishing a Git repository/release that installers or marketplaces index: GitHub CLI can validate a repository and create a release, while Vercel's CLI accepts repository and package sources. `skills.sh` exposes install counts and activity leaderboards, but no cross-marketplace star/rating standard; these metrics are popularity signals rather than quality or safety ratings. ([GitHub skill publish](https://cli.github.com/manual/gh_skill_publish), [Vercel skills CLI](https://github.com/vercel-labs/skills), [skills.sh](https://skills.sh))

**Date verified.** 2026-10-24.

**Relevance to skill-maker.** Model distribution as a source plus version/ref plus target adapters, not as a single central marketplace. Generate a canonical Git repository layout that works with `npx skills`, `gh skill`, and vendor plugins. Preserve provenance and immutable refs in generated lock/manifest data where the target supports it. Display popularity as a signal only; require inspection, publisher/source, and permission review before execution.

### 9. Ecosystem adoption and official skill libraries

**Claim.** Adoption has broadened from the early Claude/Codex/VS Code set to first-party and vendor-maintained libraries across cloud, mobile, IDE, and general coding products. The current agentskills.io showcase lists products including Claude/Claude Code, ChatGPT/Codex, GitHub Copilot/VS Code, Cursor, Cline, Gemini CLI, OpenCode, OpenHands, Goose, Kiro, Junie, OpenClaw, and many others. ([client showcase source](https://raw.githubusercontent.com/agentskills/agentskills/main/docs/snippets/clients.jsx))

**Claim.** Google maintains a large `google/skills` repository with skills and plugin manifests, distributed through `npx skills`; Expo's official skills page (modified October 1, 2026) documents one plugin usable in Claude Code and Codex, automatic/imported use in Cursor, and `skills`-CLI installation for other agents. ([Google skills repository](https://github.com/google/skills), [Expo skills](https://docs.expo.dev/skills/))

**Claim.** Azure Databricks' October 7, 2026 documentation now provides a Databricks CLI `aitools` installer, a maintained Databricks skills repository, plugin marketplace routes, and an explicit deprecation notice that the older AI Dev Kit skills should be uninstalled to avoid conflicts. It also warns that marketplace listings can lag behind the CLI/repository. ([Azure Databricks agent skills](https://learn.microsoft.com/en-us/azure/databricks/agent-skills/))

**Claim.** Gemini CLI's official page states that the CLI was replaced by Antigravity CLI for some users on June 18, 2026; Antigravity documents the successor's `.agents/skills` default, plugin installation, and slash-command conversion. ([Gemini CLI skills](https://geminicli.com/docs/cli/skills/), [Antigravity skills](https://antigravity.google/docs/skills))

**Claim.** Anthropic now exposes a beta Skills API in addition to local Claude Code skills. Its API schema documents the `skills-2025-10-02` beta feature flag, and `POST /v1/skills` uploads a bundle whose top-level directory must include `SKILL.md`; it returns a skill ID and latest-version ID, supports custom/Anthropic/example/plugin sources, and provides create/list/get/delete and version/content endpoints. The Messages API can load up to 20 skill IDs into a reusable code-execution container, using a skill version ID or `latest`. ([Anthropic Skills API](https://platform.claude.com/docs/en/api/beta/skills), [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages))

**Claim.** Current Claude Code also supports account-synced skills across terminal, Cowork, and cloud sessions, plugin/managed-settings distribution, and on-demand migration of oversized `CLAUDE.md` procedures into skills. Custom commands are merged into skills: existing `.claude/commands/<name>.md` files continue to work, while `.claude/skills/<name>/SKILL.md` adds supporting files and richer frontmatter. Local personal skills do not automatically appear in Cowork/cloud sessions, while account-synced skills can update during terminal sessions without a restart; this is a host-specific lifecycle beyond the portable file format. ([Claude Code skills](https://code.claude.com/docs/en/skills))

**Date verified.** 2026-10-25; Databricks page metadata reports `2026-10-07`, and Expo page metadata reports 2026-10-01.

**Relevance to skill-maker.** Treat vendor-owned skill repositories as valuable compatibility fixtures and corpus examples, not as proof that every optional field is portable. Add import/export tests against representative Google, Expo, Databricks, Anthropic API, and GitHub skills. For hosted Anthropic targets, preserve the workspace, skill ID, version ID, and account/cloud scope separately from the canonical bundle. Track client adoption and deprecation notices separately from spec changes.

### 10. Emerging companion standards and registry integration

**Claim.** The agentskills.io repository still has no adopted lockfile, source, signing, or SemVer extension in the normative specification, but its October 2026 discussions show active demand for those layers. Discussion #588 proposes a `skills-lock.json` companion with per-file SHA-256 pins, bundle tree hashes, machine-readable modified/missing/untracked states, provenance/attestation fields, fail-closed per-skill updates, and verify-before-load staging; the proposal remains a community draft with governance unresolved. A separate SemVer RFC is marked closed/proposal rather than an adopted standard. ([skills-lock discussion #588](https://github.com/agentskills/agentskills/discussions/588), [SemVer proposal #415](https://github.com/agentskills/agentskills/discussions/415), [current specification](https://agentskills.io/specification))

**Claim.** Tool vendors are implementing portions of this problem independently: Vercel's installer records source and skill-folder hashes, GitHub CLI records source/ref/tree SHA in frontmatter, and JetBrains AI Assistant (2026.2, built October 20, 2026) can import Claude/Codex skills, add external GitHub registries, show source metadata, and install at IDE/project/client-global scopes. ([Vercel skills CLI](https://github.com/vercel-labs/skills), [GitHub Copilot skill installation](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [JetBrains AI Assistant skills](https://www.jetbrains.com/help/ai-assistant/agent-skills.html))

**Date verified.** 2026-10-24; lockfile discussion opened 2026-10-01, and JetBrains documentation reports build date 2026-10-20.

**Relevance to skill-maker.** Do not present `skills-lock.json`, SemVer, signatures, or source metadata as agentskills.io requirements. Design skill-maker's package model so it can emit/consume provenance and immutable refs without coupling the canonical `SKILL.md` to an unadopted extension. Treat the discussion proposals as signals for a future compatibility adapter, not as a stable contract.

### 11. Security, permissions, and trust are now part of good skill UX

**Claim.** The agentskills.io client guide recommends trust gating repository-level skills because a cloned project can contain untrusted instructions. GitHub's official docs go further by warning that downloaded skills are unverified and may contain prompt injections or malicious scripts, recommending `gh skill preview` before installation and careful review before allowing shell/bash. Gemini CLI documents a user consent step that shows the skill purpose and directory path before activation, and a `--consent` option for explicitly accepting install risk. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [GitHub Copilot skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [Gemini CLI skills](https://geminicli.com/docs/cli/skills/))

**Claim.** GitHub also recommends omitting `allowed-tools` for unreviewed skills because pre-approving shell/bash removes confirmation and can enable attacker-controlled execution. The open specification itself labels `allowed-tools` experimental and warns support varies. ([GitHub Copilot skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [specification](https://agentskills.io/specification))

**Date verified.** 2026-10-24.

**Relevance to skill-maker.** Make trust, source, requested permissions, and bundled executable files visible during install. Default generated skills should omit `allowed-tools`; if a user adds it, explain the security consequence and show the exact tool patterns. Do not imply that format validation is a safety review.

## What hasn't changed

These patterns from the September 30 research remain supported by the current primary sources:

- **Portable format:** a directory with `SKILL.md`, YAML frontmatter, Markdown body, and optional supporting files. The required portable fields remain `name` and `description`. ([specification](https://agentskills.io/specification))
- **Progressive disclosure:** catalog metadata first, full instructions on activation, and scripts/references/assets only when needed. ([specification](https://agentskills.io/specification), [client implementation guide](https://agentskills.io/client-implementation/adding-skills-support))
- **Description-driven activation:** descriptions should state both capability and use case, and should use concrete domain/task terms. ([specification](https://agentskills.io/specification), [description optimization](https://agentskills.io/skill-creation/optimizing-descriptions))
- **Focused bodies:** include what the model would otherwise get wrong—local conventions, non-obvious edge cases, procedures, and examples—rather than generic domain introductions. ([best practices](https://agentskills.io/skill-creation/best-practices))
- **Lean bodies and on-demand references:** keep `SKILL.md` below the recommended 5,000 tokens/500 lines and make reference-loading conditions explicit. ([specification](https://agentskills.io/specification), [best practices](https://agentskills.io/skill-creation/best-practices))
- **Scripts for deterministic work:** prefer tested, noninteractive scripts with clear inputs, outputs, prerequisites, and error messages; pin dependencies when invoking external runners. ([using scripts](https://agentskills.io/skill-creation/using-scripts))
- **Real execution feedback:** refine a skill from traces and outputs, not only from a final answer that looked plausible. ([best practices](https://agentskills.io/skill-creation/best-practices), [evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills))
- **Portable discovery convention:** `.agents/skills/` remains widely adopted, but the format still does not mandate a filesystem location. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [quickstart](https://agentskills.io/skill-creation/quickstart))

## What's new or shifted since the September 30 check

1. **No normative spec shift.** A fresh read of the live specification and repository history found no schema, required-field, naming, triggering, or spec-version change since the prior refresh. The latest visible `main` commit remains the August 9 OpenClaw showcase change. ([specification](https://agentskills.io/specification), [repository history](https://github.com/agentskills/agentskills/commits/main))
2. **Evaluation tooling has matured materially.** Waza's October 20, 2026 `v0.39.0` release and the VS Code Waza integration add a practical path from skill requirements to deterministic checks, coverage, evidence, and CI; Claude Code's bundled `build-eval` and `hillclimb` provide a separate host-specific path for creating and iteratively optimizing evals. These are ecosystem tools, not changes to the agentskills.io format. ([Waza Quick Start](https://microsoft.github.io/waza/quick-start/), [Waza eval guide](https://microsoft.github.io/waza/guides/eval-yaml/), [VS Code customization overview](https://code.visualstudio.com/docs/agent-customization/overview), [Claude Code skills](https://code.claude.com/docs/en/skills))
3. **Discovery and package management have become normal product features.** Vercel's `skills`/`skills.sh`, GitHub's preview `gh skill` suite, VS Code's experimental marketplace, and OpenAI's universal plugin directory plus local/repository marketplaces now cover search, preview, install, update, pinning, source identity, and/or repair. The agentskills.io repo itself remains specification/showcase-focused rather than a registry. ([Vercel skills](https://github.com/vercel-labs/skills), [skills.sh](https://skills.sh), [GitHub CLI skill manual](https://cli.github.com/manual/gh_skill), [VS Code customization overview](https://code.visualstudio.com/docs/agent-customization/overview), [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [contribution policy](https://github.com/agentskills/agentskills/blob/main/CONTRIBUTING.md))
4. **Vendor distribution is increasingly plugin-plus-skill rather than raw-folder-only.** OpenAI's docs explicitly recommend plugins for reusable distribution; Google, Expo, Databricks, and other vendors publish skill bundles with plugin/manifests and client-specific install instructions. ([OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins), [Google skills](https://github.com/google/skills), [Expo skills](https://docs.expo.dev/skills/), [Azure Databricks agent skills](https://learn.microsoft.com/en-us/azure/databricks/agent-skills/))
5. **Client divergence is more visible and operationally important.** Current docs expose conflicting precedence policies, nested-directory scoping, client-specific invocation controls, separate manifests, and different consent/permission models. The portable file itself is converging while the host integration is not. ([Cline](https://docs.cline.bot/customization/skills), [Cursor](https://cursor.com/docs/skills), [Codex](https://developers.openai.com/codex/skills), [Claude Code](https://code.claude.com/docs/en/skills), [VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills), [OpenCode](https://opencode.ai/docs/skills/))
6. **Some earlier distribution paths are now explicitly obsolete or secondary.** OpenAI's old standalone `openai/skills` catalog is deprecated in favor of plugins, and Azure Databricks marks AI Dev Kit skills as deprecated in favor of its maintained agent-skills repository/CLI. Marketplace listings may also lag their source repositories. ([deprecated OpenAI skills repository](https://github.com/openai/skills), [Azure Databricks agent skills](https://learn.microsoft.com/en-us/azure/databricks/agent-skills/))
7. **Companion standards are emerging without being adopted.** The October `skills-lock.json` discussion proposes integrity pins, provenance, attestations, and verify-before-load; JetBrains has added external registry and multi-scope import/install UX. Skill-maker should expose these as adapters while keeping them clearly separate from the stable core format. ([lockfile discussion](https://github.com/agentskills/agentskills/discussions/588), [JetBrains AI Assistant skills](https://www.jetbrains.com/help/ai-assistant/agent-skills.html))
8. **Hosted skill lifecycle is becoming a distinct distribution mode.** Anthropic's beta Skills API uploads and versions bundles for server-side containers, while Claude Code account sync spans terminal, Cowork, and cloud sessions; this creates version, workspace, and scope concerns beyond local file discovery. ([Anthropic Skills API](https://platform.claude.com/docs/en/api/beta/skills), [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages), [Claude Code skills](https://code.claude.com/docs/en/skills))

## What's becoming obsolete or discouraged

- **Treating `SKILL.md` as a complete portability contract.** The file is portable; discovery paths, precedence, optional fields, permissions, and packaging are not. Test the core artifact and host adapters independently. ([client implementation guide](https://agentskills.io/client-implementation/adding-skills-support), [Cursor](https://cursor.com/docs/skills), [Codex](https://developers.openai.com/codex/skills))
- **Putting every client extension in portable frontmatter.** Extensions such as `paths`, `context: fork`, `disable-model-invocation`, and `agents/openai.yaml` are useful but host-specific. Keep them in opt-in overlays or manifests. ([VS Code](https://code.visualstudio.com/docs/agent-customization/agent-skills), [Cursor](https://cursor.com/docs/skills), [Codex](https://developers.openai.com/codex/skills))
- **Relying on one happy-path demo.** Current evaluation guidance expects negative/near-miss, boundary, baseline, assertion, trace, timing, and human-review evidence; Waza explicitly says mocks do not prove agent quality. ([evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills), [Waza eval guide](https://microsoft.github.io/waza/guides/eval-yaml/))
- **Blind installation from a repository or marketplace.** Preview, inspect scripts/references, identify the publisher/source, pin a ref where possible, and review requested permissions. GitHub explicitly warns that skills are unverified. ([GitHub Copilot skills](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills), [GitHub CLI preview](https://cli.github.com/manual/gh_skill_preview))
- **Using `skills-ref` as a production runtime or SDK.** The reference library's own README says it is demonstration-only. ([skills-ref README](https://github.com/agentskills/agentskills/blob/main/skills-ref/README.md))
- **Using the deprecated `openai/skills` repository as the primary distribution channel.** OpenAI's repository directs users to plugins, and the current Codex docs recommend plugins for reusable distribution. ([deprecated repository](https://github.com/openai/skills), [OpenAI plugin packaging](https://developers.openai.com/plugins/build/plugins))
- **Copying a skill manually into every client directory as the only update strategy.** Multi-agent installers now provide symlink/copy choices, update detection, refs/pins, and provenance; manual copies make drift and provenance difficult to audit. ([Vercel CLI](https://github.com/vercel-labs/skills), [GitHub Copilot skill installation](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills))
- **Assuming local availability implies cloud availability.** Claude Code's personal filesystem skills do not automatically load in Cowork or cloud sessions; account sync, repository commits, plugin distribution, or explicit managed settings are separate delivery paths. ([Claude Code skills](https://code.claude.com/docs/en/skills))
- **Using a mutable hosted `latest` reference when reproducibility matters.** Anthropic's Skills API exposes both `latest` and immutable version IDs; production workflows should record the chosen version ID and update deliberately. ([Anthropic Skills API](https://platform.claude.com/docs/en/api/beta/skills), [Anthropic Messages API](https://platform.claude.com/docs/en/api/messages))
- **Starting new Claude Code procedures in `.claude/commands/` instead of skills.** Command files remain supported for compatibility, but Claude Code recommends skills for new work because skills can bundle supporting files and richer frontmatter. ([Claude Code skills](https://code.claude.com/docs/en/skills))

## Recommendations for skill-maker

1. **Keep a strict portable core.** Generate only the normative `name`, `description`, and optional portable fields by default. Keep client behavior in explicit profiles/overlays: Claude Code/VS Code invocation controls, Cursor `paths`, Codex `agents/openai.yaml`, and plugin manifests. Show a portability report that identifies every extension.
2. **Make installation target-aware.** Ask whether the user wants a repo skill, personal skill, plugin, local/repository marketplace entry, or package. Offer `.agents/skills/` as the interoperability default, then show each selected client’s native location and collision/precedence behavior. Do not claim that one path works on every surface.
3. **Build descriptions from trigger tests.** Generate 8–10 should-trigger, 8–10 should-not-trigger, and near-miss prompts. Run each several times, report trigger rates, and keep a fixed validation split. Put the main capability and trigger language first so descriptions remain useful after host truncation.
4. **Ship a compact eval scaffold.** Create `evals/evals.json` with realistic prompts, expected outputs, optional fixtures, and mechanically checkable assertions. Include a baseline mode and record token/time deltas. Offer Waza export for teams that need CI, deterministic graders, coverage checks, evidence, or multi-model comparison.
5. **Separate deterministic checks from qualitative judgment.** Prefer file/JSON/schema/exit-code/action checks for objective requirements; use an LLM judge only for genuinely qualitative properties. Make “mock plumbing passed” distinct from “real agent behavior passed.”
6. **Enforce progressive-disclosure budgets.** Warn when `SKILL.md` exceeds 500 lines or 5,000 tokens, flag references deeper than one level, and require every referenced resource to have an explicit load condition. Encourage focused gotchas, defaults, examples, and validation loops over encyclopedic prose.
7. **Make executable content inspectable and safe.** List bundled scripts in the UI, show prerequisites and requested tools, require noninteractive help/error behavior, and default to no `allowed-tools`. Treat trust review as separate from metadata validation.
8. **Generate reproducible distribution metadata.** For Git/marketplace targets, retain source repository, ref/tag/SHA, version, and installed target; for hosted targets, retain workspace, skill ID, version ID, and whether `latest` or an immutable version is requested. Support `npx skills` and `gh skill` conventions where appropriate, and offer plugin manifests for clients that use them. Never conflate popularity/install counts with safety or correctness.
9. **Maintain a compatibility corpus.** Periodically import representative official/vendor skills from Google, Expo, Databricks, Anthropic, GitHub, and OpenAI; test required-field parsing, extension handling, path resolution, scripts, and resource loading. Track client deprecations separately from normative spec changes.
10. **Document the boundary with always-on instructions.** Explain that `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, and client instruction files are different mechanisms from on-demand skills. Put universal repository policy in the always-on mechanism and task-specific procedures in skills. ([VS Code customization concepts](https://code.visualstudio.com/docs/agents/concepts/customization), [Codex build-skills](https://developers.openai.com/codex/skills), [Claude Code skills](https://code.claude.com/docs/en/skills))
